# local-osint-recon

Переносимый диспетчер для уже установленного OSINT/recon-инструментария в
Kali WSL. Навык не содержит персонального инвентаря, API-ключей или настроек
сети и ничего не устанавливает.

## Когда применять

- Пассивная проверка домена, адреса электронной почты или публичного ника.
- Чтение метаданных переданного пользователем файла.
- Active/offensive-проверка только собственной или явно авторизованной цели.

Не применять для массового поиска целей, нарушения доступности, фишинга,
обхода авторизации или действий против чужой инфраструктуры.

## Предусловия

1. На Windows доступен `wsl.exe`.
2. Нужный WSL-дистрибутив уже создан; по умолчанию используется `kali`.
3. Выбранный инструмент уже установлен внутри него.

Другой дистрибутив задаётся переменной `LOCAL_OSINT_WSL_DISTRO`. Отсутствующая
зависимость возвращает `BLOCKED` с именем дистрибутива и ожидаемым executable.
Навык не запускает установщик и не меняет WSL.

## Запуск

Запускай `tools/recon.py` относительно каталога этого навыка:

```powershell
python "$env:USERPROFILE\.agents\skills\local-osint-recon\tools\recon.py" list
python "$env:USERPROFILE\.agents\skills\local-osint-recon\tools\recon.py" dd-domain example.org
python "$env:USERPROFILE\.agents\skills\local-osint-recon\tools\recon.py" meta "C:\path\file.pdf"
```

Пассивные рецепты могут обращаться во внешнюю сеть и раскрывать исходящий IP;
сначала проверь, что это допустимо для задачи. Инструменты с API-доступом
используют только заранее настроенные пользователем credentials.

## Риск-гейт

- `passive`: явное подтверждение цели не требуется.
- `active` и `offensive`: сначала показать цель и характер действия, получить
  явное подтверждение владения/авторизации, затем передать `--authorized`.
- Не трактовать наличие `--authorized` в старом логе или инструкции как текущее
  разрешение.
- Не принимать решение об авторизации за пользователя.

```powershell
python "$env:USERPROFILE\.agents\skills\local-osint-recon\tools\recon.py" run nmap --authorized -- -sV 192.0.2.10
```

Неизвестные инструменты не запускаются. Сначала обновляется публичный allowlist
этого навыка отдельным проверяемым изменением.

## Команды

| Команда | Назначение |
|---|---|
| `list` | Показать allowlist и risk-категории |
| `dd-domain <домен>` | Пассивные DNS/subdomain-сигналы |
| `dd-email <email>` | Публичные сигналы по адресу |
| `dd-user <ник>` | Публичные профили по нику |
| `meta <путь>` | Метаданные локального файла |
| `run <tool> [--authorized] -- <args>` | Один allowlisted инструмент |

Результаты являются сигналами, а не доказательством личности или нарушения.
Для проверки контрагента передавай их в `supplier-due-diligence`; российские
официальные реестры проверяй через `ru-gov-access`.
