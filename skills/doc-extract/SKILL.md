# Извлечение из PDF: маршрутизация по типу листа

**Лидера-инструмента НЕТ. Выбор — по типу страницы. Проверяй текст-слой ПЕРВЫМ (дёшево, локально, без облака).**

## Дерево решений
1. **Есть текст-слой?** `len(fitz.open(pdf)[i].get_text().strip()) > 50`
   - **ДА, обычный документ** → **pymupdf** (`fitz.get_text()`): ~0.03 с, чисто, локально, 0 облака.
     НЕ гнать текст-слой в MinerU-облако/docling — в сотни раз медленнее без выгоды.
   - **ДА, вектор-чертёж (CAD-экспорт)** → **pymupdf** берёт выноски/экспликацию/штамп текстом.
     ⚠ «битый cmap»: часть выносок встроенным чертёжным шрифтом → каша. Если каша — добить OCR (docling-OCR-ветка чище текст-слоя на таких).
   - **НЕТ (скан)** → OCR (п.2).
2. **Скан без текст-слоя** → OCR, но чистого победителя НЕТ:
   - **MinerU cloud** (pipeline+ru): то отлично (декларация), то теряет тело таблицы (сертификат). Латинизирует латинские бренды (GEBERIT→GЕВЕRТ).
   - **docling** (локально, EasyOCR ru): берёт таблицы, но систематические русские OCR-ошибки (и↔н). Надёжнее по ПОКРЫТИЮ таблиц.
   - **обязательна ручная сверка** количеств/артикулов после OCR.
3. **Рукопись** → провал у ВСЕХ OCR (кириллический курсив не по зубам ни EasyOCR, ни MinerU). Только ручной ввод / спец-HTR. Даты обычно распознаются.
4. **Геометрия чертежа** (стены/оси/линии/взаимное расположение оборудования) → документ-парсеры НЕ берут (сваливают в одну картинку-подложку). Нужен CAD-слой: `autocad-mcp` / скилл `cad-reader`.
5. **Мета чертежа-PDF** (штамп, текстовые блоки с bbox, слои `/OCProperties`, помещения по легенде) → `tools/extract_drawing_meta.py` (`extract_text_blocks`, `find_stamp_data`) + справка `references/drawings.md`.

## Инструменты (tools)
- **pymupdf (fitz)** — рабочая лошадка текст-слоя. Локально, всегда. ~90% текста ИД сюда.
- **MinerU cloud** — `python ~/.agents/skills/doc-extract/tools/mineru_extract.py <pdf> --lang ru` (pipeline+ru — **НЕ vlm**, vlm калечит кириллицу; авто-сплит томов >180 стр на батчи + склейка; секрет только из `MINERU_API_TOKEN`). Внешняя capability должна быть подключена пользователем заранее.
  **Приватность:** облако mineru.net (КНР) — НЕ для конфиденциального ИД без явного разрешения владельца.
- **docling** — локально, без лимитов/токена (подстраховка для неавторизованных / больших томов). ⚠ НЕ drop-in на Win+кириллица: нужен junction для ASCII-пути Python + transformers≥5.
- **EasyOCR (ru+en, torch) — рабочий локальный OCR-baseline** (torch переваривает кириллицу в пути). Для сканов на этой машине — брать ЕГО. ⚠ **paddleocr на Win+кириллица НЕ работает:** 3.5 = PIR-краш, 2.9 = C++ paddle не открывает модель под не-ASCII путём `~/.paddleocr` (то же, что ломало docling); лечится только ASCII-junction для model-home. Вывод: OCR-baseline = **easyocr**, не paddleocr.

## Лимиты MinerU cloud
Precision (с бесплатным токеном): ≤200 МБ, ~200–600 стр/файл, ~1000–2000 стр/день. Без токена (Flash): 10 МБ / 20 стр. Большие тома → хелпер режет на батчи автоматически.

## Ловушки извлечения (унаследованы из pdf-helper)
- **Сдвиг колонок при извлечении таблиц нагрузок.** При экспорте PDF из расчётных программ/CAD числовые таблицы (Pр, Sр, мощности по щитам) могут «съезжать» на колонку при `extract_tables()`/`find_tables()` — значение попадает не в свой столбец. **Любые числа из таблиц нагрузок/мощностей сверять с оригиналом** (рендер страницы глазами или соседний столбец-сумма), не доверять плоскому парсу. Особенно при аудите «ТЧ vs спецификация».
- **CID / PScript-Distiller PDF — читать рендером, не текстовым слоем.** PDF, прошедшие через PostScript-принтер + Acrobat Distiller (Producer `PScript5`/`Acrobat Distiller`), часто имеют CID-шрифты без ToUnicode → `extract_text()` отдаёт мусор/пусто. Не биться об текст — сразу **рендер ≥180 dpi** (`pdf_render_pages` / PyMuPDF `get_pixmap(dpi=180)`) + читать визуально/OCR.
- **«PDF file not found» на живом файле с «ё»/«й» в имени — NFD-имя.** Файлы из внешних источников (СберБанк-онлайн, macOS-цепочки) приходят с NFD-именами (`е`+U+0308 вместо `ё` U+0451); модель печатает пути только в NFC, NTFS не нормализует → точного пути не существует, хотя Glob по `*`-маске файл видит. Бьёт по любому инструменту с литеральным путём (pdf-mcp, word-MCP, `core.files.read`, `open()`) — сервер не виноват, «перепечатать внимательнее» не поможет никогда (LLM не может эмитить NFD). Детект: not found + Glob видит + ё/й в имени. Обход: wildcard вместо спорной буквы (`сч*та`) → копия под ASCII-имя; программно `unicodedata.normalize("NFC", n)`-матчинг по `os.listdir`; лечение — переименовать в NFC. (Инцидент + эксперимент NFC/NFD-парами, 2026-07-11; anti-patterns A3.10.)

## Соседи (разграничение)
- **Редактировать PDF** (merge/split, страницы, формы AcroForm, аннотации/облачка, watermark, правка вектор-чертежей) → skill `pdf-edit`.
- **OCR скана со структурой (bbox, label→value) / замена текста на скане** → skill `image-text-replace` (доменный OCR-стек: EasyOCR + smart cap + neighbor cell).
- **Содержательная сверка/diff таблиц СО (спецификаций)** → skill `co-verify` (координатное извлечение + детерминированный матчинг; общее извлечение — сюда, в doc-extract).
- **Геометрия DWG/CAD** → skill `cad-reader` / `autocad-mcp`.
