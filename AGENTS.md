# OpenCode Base

Отвечай на языке пользователя. Имена файлов, команд и параметров сохраняй в
исходной форме.

## Рабочий режим

- Простой разговор и короткое объяснение выполняй без tools, subagents и
  reviewer-процедур.
- Перед существенным изменением проверь реальные файлы и используй нативный
  режим планирования. Отдельный brainstorming workflow не запускай.
- Полный skill загружай только через native skill tool после совпадения с его
  кратким описанием. Supporting files читай по необходимости.
- Точную повторяемую обработку выполняй кодом раньше LLM. Массовую делегацию
  не запускай по умолчанию.

## Маршрутизация

- Расчёты и подбор инженерного оборудования → `designer`.
- Объёмы, ВОР и спецификации → `pto-engineer`.
- Сметы и КС-2/КС-3 → `smetchik`.
- Снабжение и УПД → `snabzhenets`.
- Исполнительная документация → `id-engineer`.
- Точная нормативная цитата → `norm-lookup`; не цитируй нормы по памяти.
- Один раздел по нормам → `audit-rd-section`; несколько разделов →
  `rd-coordinator`.

Reviewer нужен для выдаваемых документов, количеств, нормативных ссылок и
дорогих либо необратимых решений. Форму проверяет профильный reviewer,
содержание по источникам — `auditor`. Для простого ответа и диагностики
reviewer не нужен. Недоступное для проверки не является PASS.

## Provider, инструменты и данные

- Provider, модель и reasoning/effort выбирает пользователь; база их не
  фиксирует и не включает fallback.
- Permissions для внешней сети, shell и записи не обходи. Отсутствующий
  обязательный tool даёт `BLOCKED` с точной инструкцией.
- Не изменяй авторизацию, сессии, plugins, проекты и рабочие папки.
- Публичный share отключён. Обновления идут только hub → consumer и
  устанавливаются явно через `$sync-base`.
- Никакие сессии, документы, локальные изменения и учётные данные обратно не
  отправляются.
