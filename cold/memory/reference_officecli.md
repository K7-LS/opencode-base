# OfficeCLI — работа с Office-файлами через один бинарь

Загружать по триггерам: «officecli», «править docx без Word», «собрать презентацию
pptx», «отрендерить документ в картинку для проверки», «нужен CLI для Office-файлов»,
а также когда правка .docx/.xlsx через python-docx/openpyxl ломает оформление.

Оценён 2026-08-07 по harvest-протоколу. Метаданные сверены через GitHub API, не по README.

## Что это

`https://github.com/iOfficeAI/OfficeCLI` — Apache-2.0, C#/.NET, self-contained бинарь
~32 МБ на платформу. Читает и правит .docx/.xlsx/.pptx без установленного Office и без
Python-стека. На 2026-08-07: 26 492 stars, 30 релизов, последний `v1.0.143` от 2026-07-28.

Адресация узлов документа путями (`/body/p[3]`, `/Sheet1/B2`), три уровня работы —
чтение, правка DOM, сырой XML. У всех команд есть `--json`.

## Зачем он нам

**Рендер для проверки.** `officecli view --screenshot` (а также `html`, `pdf`, `svg`)
отдаёт картинку документа через headless-браузер. Это закрывает главный провал правки
docx — сдачу «готово, проверено» без единого взгляда на вёрстку.

**Правка живого файла вместо пересборки.** Точечная замена свойства узла не рушит
плавающие логотипы, табы и подчёркивания полей бланка — то, на чём стабильно ломается
пересборка документа с нуля.

**Excel:** селекторы с булевой логикой работают и на запись —
`cell[value>5000 or value<100]`, `:has(formula)`, `:empty`, выборка строк по имени
колонки `Sheet1!row[Salary>5000]`. Сортировка тащит за строками гиперссылки, комментарии,
условное форматирование и отказывается сортировать диапазоны с объединёнными ячейками
или формулами. Сводные таблицы с полной схемой.

**PowerPoint:** shapes/pictures/tables/charts/connectors/groups, адресация по имени
(`shape[@name=Title 1]`), рендер слайда в SVG/PNG. Здесь выигрыш наибольший — иных
инструментов под pptx у нас нет.

## Ограничения, которые надо знать заранее

- `find` в Excel — только find + replace, без форматирования по найденному (в Word есть).
- `.xlsx` не отдаёт `data-path`, поэтому `mark` и чтение выделения на нём всегда
  `stale=true`. Сценарий «пользователь кликнул ячейку — агент прочитал» для Excel
  не работает, для docx/pptx работает.
- Под-скиллы `financial-model` и `data-dashboard` заточены под западные бизнес-формы,
  не под сметы и ВОР по ГЭСН/ФЕР.

## Установка — только вручную

Скачать бинарь со страницы релизов GitHub и **сверить с `SHA256SUMS`** оттуда же.

Чего делать нельзя и почему:

- `curl -fsSL https://d.officecli.ai/install.sh | bash` и `irm .../install.ps1 | iex` —
  установочный скрипт при недоступности файла сумм печатает «Checksum file not available,
  skipping verification» и **продолжает установку**. Подпись он не проверяет вовсе.
- `officecli install` — раскладывает свой скилл по всем обнаруженным агентским каталогам
  и правит пользовательский PATH. Компонент, появившийся в базе мимо штатной установки,
  ломает управляемую поверхность и разъезжается по машинам неконтролируемо.
- Инструкцию «дайте агенту `curl -fsSL https://officecli.ai/SKILL.md`», которой инструмент
  рекламируется, выполнять нельзя: это исполнение инструкций с живого неверсионированного
  домена. Тот же файл лежит в репозитории под контролем версий — читать надо его.

Первый прогон делать на копиях реальных документов, а не на боевых, и обязательно
проверять результат через `view --screenshot`.
